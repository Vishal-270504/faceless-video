Your API has a rule: titles need at least 3 characters. But the controller checks for 5. Now a 4-letter title passes one check and fails the other.

Why? The rule lives in two places. Two copies of a rule always drift apart.

Here's a clean split. Each layer has one job.

The controller reads the request and returns the answer. Nothing else.

The service holds the rules: validation, ownership and cache updates.

The repository only stores and finds data.

Every write goes through the service, so the rule always runs.

Want a different database? Change one line in Program.cs. The controller and service stay the same.

The takeaway: a rule in two places will drift apart. Keep it in one.
