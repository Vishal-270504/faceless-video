You want to try a big change, but you fear breaking the trunk, the main line of your code. Here is the safe way.

A branch is a separate line of work. You change things there, and the trunk stays untouched until you are happy.

Example: you create a branch called dark-mode and change twenty files. It looks bad. You delete the branch, and the trunk never changed.

In the terminal, git switch -c dark-mode creates the branch and opens it.

When it works, you merge it into the trunk, usually through a pull request.

Takeaway: one branch per change, and never work straight on the trunk.
