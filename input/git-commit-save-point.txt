You changed a file, something broke, and you cannot remember what worked. Sound familiar?

A commit is a save point. It stores your files at one moment, with a short note, so you can go back to it later.

Used for: undoing mistakes, seeing what changed, and sharing work with a team.

Example: you commit your login page while it works. Then you break it while adding a button. You go back to that save point, and the login works again.

In the terminal, git commit saves the save point with a message.

Takeaway: commit when something works, and write down what you did.
